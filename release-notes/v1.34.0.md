# Blockfield/blockfield-mod v1.34.0

## Кратко

Мод 1.34.0 выносит блоки оформления карт в отдельный мод blockfield-decor
(версия 1.0.1 обязательна: decor 1.0.1 не работает с blockfield <1.34.0).
Id блоков сохранены (`blockfield:*`), ассеты побайтово те же, миграция карт
не нужна. Версия 1.33.0 вышла с изменениями interact-подсказки и ещё
регистрировала блоки — именно 1.34.0 их убирает.

## Для игроков

Новое:

- Оформление карт (двери, большие двери, детали Steam 'n' Rails, палатка,
  цветное дерево, clip-листва) теперь поставляет blockfield-decor 1.0.1;
  видимых изменений нет.

Исправления:

- Сведений о точечных игровых исправлениях в промежутке 1.33.0 → 1.34.0
  сверх выноса декора нет (см. «Источники»).

Изменения поведения:

- Требуется blockfield-decor ≥1.0.1: несовпадающая пара падает при загрузке
  и не портит сохранения.

## Технические изменения

- `common`: ModBlocks, block/* и теги дверей удалены; BlockFieldCommon больше
  не регистрирует блоки.
- `client`: ModBlockRenderLayers и BlockElementBoundsMixin переехали в decor;
  модели, текстуры и lang-ключи блоков удалены.
- `server`: isInteractiveBlock больше не проверяет класс BigDoorBlock;
  большие двери входят в `#minecraft:doors`, который уже проверяется.
- Белый список `tacz interact_key`: явные id `blockfield:door_*` убраны
  (по сообщению коммита `c68ceb6`; полный diff см. по тегам).
- NOTICE.md, docs/railways-remap.csv, tools/import-mod-assets.py переехали
  в blockfield-decor вместе с ассетами.
- `gradle.properties`: mod_version 1.33.0 → 1.34.0.

## Обновлённые компоненты

- Зависимости мода не менялись (внешних пинов уровня *.pw.toml у мода нет).
  Изменение — внутреннее разделение на blockfield-decor 1.0.1.

## Совместимость и необходимые действия

- Требуется blockfield-decor ≥1.0.1 (на клиенте и сервере, side both).
- decor 1.0.1 обратно несовместим с blockfield <1.34.0 — обновлять парой.
- Миграция карт, хаба и рамок не нужна (id и ассеты сохранены).
